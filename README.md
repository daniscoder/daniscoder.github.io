# daniscoder.github.io

Сайт с программами для сейсмообработки: https://daniscoder.github.io.
Собирается MkDocs с темой Material из Markdown в `docs/`, выкладывается на
GitHub Pages при каждом push в `main` (`.github/workflows/pages.yml`).

Исходники программ живут в своих приватных репозиториях; здесь - только сайт и
готовые сборки в Releases.

## Посмотреть локально

```bash
py -m pip install -r requirements.txt
py -m mkdocs serve
```

Сайт откроется на http://127.0.0.1:8000 и обновляется при каждой правке. Перед
push стоит прогнать `py -m mkdocs build --strict`: он падает на битой ссылке или
картинке - так же, как сборка на GitHub.

## Устройство

| | |
|---|---|
| `docs/index.md` | главная: карточки программ, как запускать |
| `docs/<программа>.md` | страница программы: что делает, скачать, данные, результат, история версий |
| `docs/img/` | картинки - нарисованы самими программами на синтетических примерах |
| `docs/examples/` | синтетические примеры входных данных для пробы, реальных данных здесь нет |
| `mkdocs.yml` | название, тема, меню |

## Выпуск версии

У каждой программы один постоянный релиз с тегом по ее имени: `histogram_for_reg`,
`polygon`, `lmoToXY`. Ссылки «Скачать» на сайте ведут на
`releases/download/<тег>/<файл>` и при новой версии не меняются. Общая ссылка
`releases/latest` здесь не годится: она ведет на последний релиз вообще, а не на
последний у конкретной программы.

Первый раз релиз заводится так (файлы - из `dist/` программы, собранные на
Windows и на Linux):

```bash
gh release create polygon polygon.exe polygon --title "polygon" --notes "Версия 2.5.0"
```

Новая версия заменяет файлы в том же релизе:

```bash
gh release upload polygon polygon.exe polygon --clobber
```

После этого поменять номер версии и строку в «Истории версий» на странице
программы.
